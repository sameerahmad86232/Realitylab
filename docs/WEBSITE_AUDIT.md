# RealityLab: candid product, UI and hackathon audit

Audit date: October 28, 2026. Scope: local repository and production build, Chromium desktop/tablet/mobile, injected-provider workflows, existing recorded live-provider evidence, dependency checks. The public Render deployment was not available for verification. No additional paid inference was used for this audit.

## Verdict

The app is an interactive object-explanation prototype with approximate component geometry. It is **not yet a reliable object-to-functional-blueprint system**. UI polish alone will not make that claim true. I would not present it as reconstructing every object, finding all internal parts, or generating build-ready engineering plans. I would demonstrate one complete physical task with honest evidence, while retaining broad object exploration.

The most competitive assets already present are the photo-linked component graph, explicit uncertainty, user corrections, local 3D inspection and deterministic measurement tools. The weakest assets are shape fidelity, proof of impact, and lack of a demonstrated physical outcome. This is a qualitative audit, not a prediction of judges' scores or a ruling on eligibility.

## Changes completed in this audit

- Moved the object workspace directly after the hero; moved the visual catalog and process explanation below it.
- Replaced vague hero copy with the actual photo → 3D concept → explanation workflow.
- Increased functional text, form controls and touch targets; shortened the mobile hero; removed the large decorative glyph that competed with mobile about-section copy.
- Added a keyboard skip link, arrow/Home/End tab navigation, single tab stops, and navigation expanded state.
- Added an explicit fixed car-sample notice and removed its simulated processing delay.
- Added a waiting/cancellation explanation for live analysis; removed developer-only setup instructions from network errors.
- Cleared stale health state on a failed recheck; cleaned up sample preview object URLs; fixed all previously failing frontend lint errors.
- Converted four presentation assets to WebP: 6,870,814 bytes total → 285,032 bytes, about 95.9% smaller. Original PNG sources remain in the repository; runtime imports use the WebP derivatives.
- Updated the image-processing dependency to sharp 0.35.5. The full dependency check also identified development-server Vite/esbuild advisories; upgraded Vite to patched 6.4.5 within the existing React plugin’s supported range. Final root/frontend dependency reports show zero reported advisories, including dev dependencies. This does not establish that the app has no security weaknesses.

## Verification and limits

Production build and complete frontend lint passed. The existing 55 unit/API tests and general browser, shader, camera/CAD and scan suites passed after the main UI changes. Tests were repeated where the image dependency changed.

A new reproducible `npm run test:ui-audit` checks a scan-result workflow at 1440, 768, 390 and 320 pixels: keyboard navigation, skip link, sample disclosure, 16 px visible form fields, document overflow, missing images and uncaught page errors. Supplying `AXE_PATH` adds axe-core checks. The audit used axe-core 4.10.3 with WCAG 2 A/AA and 2.1 AA tags; the tested result states had no reported violations at those widths. The pre-change empty workspace/inspector/sample states also had no reported axe violations: the visual weaknesses were largely usability and hierarchy, not detected WCAG failures. This is not a complete accessibility certification, screen-reader audit, or physical-device test.

Browser fixtures are injected and spend no credits. Their screenshots are labeled fixtures; they are not proof of model accuracy. Existing live provider checks are documented separately. No public deployment, organizer eligibility determination, physical manufacturing result or universal reconstruction capability was verified.

## Recommended next build, before more visual decoration

1. **Define the promise:** broad object exploration with an editable approximate component model; no “all parts” or “working blueprint” claim.
2. **Prove one real task:** record a new object from several views, review/correct the parts, perform a supported measurement check, and produce a usable exported record. Use newly built event features and identify baseline/third-party contributions.
3. **Make refinement real:** obtain a missing view or measurement, preserve the old result, reconcile component IDs and show exactly which uncertain claim changed. Do not replace the whole report without a reviewable diff.
4. **Evaluate rather than cherry-pick:** publish the held-out cases, error counts, timing and required human corrections. Test failed requests and unknown objects live.
5. **Verify the deployed experience:** private-browser upload, camera permissions, cancellation, downloads, mobile layout, cold starts and quota exhaustion, then record the three-minute demo with a visible user outcome.

Faithful arbitrary-object reconstruction and verified functional manufacturing plans are separate, substantially larger engineering goals. Adding more shaders or collecting more unrelated repositories will not close those gaps.
